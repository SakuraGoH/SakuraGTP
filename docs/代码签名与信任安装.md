# 代码签名与「未知发布者」提示处理

> 适用版本：SakuraGTP 1.6.4 及以后
> 相关文件：`certs/SakuraGTP-CodeSigning.cer`、`tools/sign_release.ps1`、`tools/install_cert.ps1`、`tools/fix_publisher_prompt.ps1`

## 1. 提示是怎么来的

Windows 在启动 exe 时可能弹两类完全不同的窗口，处理方式也不同：

| 窗口 | 触发条件 | 典型文案 |
| --- | --- | --- |
| **UAC（用户账户控制）** | 程序清单要求管理员权限（`requireAdministrator`），或文件名/路径被判定为安装程序 | 「你要允许此应用对你的设备进行更改吗？发布者：未知」 |
| **SmartScreen / 附件管理器安全警告** | 文件**未签名**，或带有「来自 Internet」的标记（Mark of the Web），且信誉不足 | 「Windows 已保护你的电脑 / 无法验证发布者」 |

SakuraGTP 的 exe 清单是 `asInvoker`（不需要管理员），因此正常双击**不会**触发 UAC。出现「发布者未知」绝大多数是第二类：**exe 没有数字签名**，而用户拿到它的途径（下载、聊天软件转发、压缩包解压）给它打上了「来自 Internet」标记。

## 2. 已做的处理（本机）

1. **生成代码签名证书**（自签名，有效期 10 年，仅用于本项目）：

   ```
   主题: CN=SakuraGTP, O=SakuraGTP Project, C=CN
   指纹: 821A43B3AEE858F1BAE570F3E81A53FEC561E65B
   ```

2. **给 `dist/SakuraGTP-v1.6.4.exe` 签名**，带时间戳；签名校验结果为 `Valid`。
3. **把证书装入当前用户的信任存储**：
   - `Cert:\CurrentUser\Root`（受信任的根证书颁发机构）
   - `Cert:\CurrentUser\TrustedPublisher`（受信任的发布者）
4. **解除文件锁定**（`Unblock-File`），去掉「来自 Internet」标记。

处理后，`Get-AuthenticodeSignature` 显示：

```
Status  : Valid
Signer  : CN=SakuraGTP, O=SakuraGTP Project, C=CN
```

## 3. 效果与边界

### 已经解决

- 在本机（已安装证书）双击 exe：显示**发布者 SakuraGTP**，不再出现「未知发布者」；
- 文件不再带「来自 Internet」标记，附件管理器的「无法验证发布者」安全警告消失；
- 程序清单为 `asInvoker`，正常双击不会弹 UAC。

### 仍然存在的限制

- **换一台没装证书的电脑**：Windows 仍会显示「未知发布者」。需要在目标机器上运行一次
  `tools\install_cert.ps1`（当前用户存储，无需管理员；加 `-Machine` 且以管理员运行则对所有用户生效）。
- **SmartScreen 云信誉**：自签名证书能让 Windows 验证「发布者是谁」，但微软 SmartScreen 的
  **信誉**来自下载量和证书类型。对外大规模分发时，仍可能第一次运行出现「Windows 已保护你的电脑」，
  需要用户点「更多信息 → 仍要运行」。要彻底消除，需要购买 **OV/EV 代码签名证书**（EV 证书可立即获得信誉），
  这是任何自签名方案都绕不过去的限制。

## 4. 日常使用

### 4.1 重新打包后签名（每次发版必做）

```powershell
powershell -ExecutionPolicy Bypass -File tools\sign_release.ps1
```

默认对 `dist` 下最新的 `SakuraGTP-*.exe` 签名；也可以指定文件：

```powershell
powershell -ExecutionPolicy Bypass -File tools\sign_release.ps1 -Exe dist\SakuraGTP-v1.6.3.exe
```

脚本会：查找证书 → 签名（时间戳不可用时自动降级为无时间戳）→ 解除锁定 → 校验，失败时以非 0 退出。

### 4.2 在另一台电脑上消除「未知发布者」

把 `certs/SakuraGTP-CodeSigning.cer` 和 `tools/install_cert.ps1` 一起拷过去，运行：

```powershell
powershell -ExecutionPolicy Bypass -File tools\install_cert.ps1
```

之后该机器信任本项目的签名（只影响签名验证，不影响系统其他安全设置）。

### 4.3 一键处理

把 exe 拷到任意位置后运行：

```powershell
powershell -ExecutionPolicy Bypass -File tools\fix_publisher_prompt.ps1 -Exe "D:\Tools\SakuraGTP-v1.6.3.exe"
```

它会依次：解除文件锁定 → 安装证书 → 校验签名并显示发布者。

## 5. 安全须知

- `certs/SakuraGTP-CodeSigning.pfx` 含**私钥**，只能留在本机；已在 `certs/.gitignore` 中排除，**不要**提交或外发。
- 私钥丢失后无法再给新版本签名（旧签名仍有效直到证书过期）；如需更换证书，重新生成并让所有机器重新安装信任。
- 自签名根证书被安装后，任何用该私钥签名的程序都会被本机信任。请妥善保管私钥，避免被他人用于签恶意程序。
- 对外分发建议：购买 OV/EV 代码签名证书，替换 `tools/sign_release.ps1` 中的证书主题即可，脚本无需改动。

## 6. 排错

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 签名脚本报「没有找到证书」 | 证书不在当前用户「个人」存储 | 运行 `tools/install_cert.ps1`，或重新生成证书 |
| 签名后仍显示「未知发布者」 | 证书未装入「受信任的根」；或文件被重新下载后又带上了 Internet 标记 | 重新运行 `fix_publisher_prompt.ps1` |
| 双击提示「Windows 已保护你的电脑」 | SmartScreen 信誉不足（自签名常见） | 点「更多信息 → 仍要运行」；对外分发请换 OV/EV 证书 |
| 提示 UAC 要求管理员 | 程序被放到了需要提权的目录，或被当成安装程序 | 放到普通目录（如 `D:\Tools\SakuraGTP\`）运行 |
| 时间戳服务器超时 | 网络受限 | 脚本会自动降级为无时间戳签名，不影响本机使用 |
| 双击提示「Could not create temporary directory!」 | `%TEMP%` 不可写、磁盘空间不足，或临时目录被安全软件拦截 | 清理 `%TEMP%`、确认磁盘有足够空间；必要时把 TEMP 指到可写目录再启动 |
## 7. 运行时目录（1.6.4 起）

onefile 版启动时要把自身解压到临时目录。1.6.4 起解压位置从 %TEMP% 改成了：

```
%LOCALAPPDATA%\SakuraGTP\runtime\_MEIxxxxxx
```

原因：部分机器的 %TEMP% 不可写、被清理工具接管或被安全软件拦截，PyInstaller 会直接报
“Could not create temporary directory!” 并退出。固定到用户自己的 LocalAppData 后，
只要该目录可写就能启动；程序退出时会自动清理 _MEI 目录。

构建时对应参数（见 uild.ps1）：

```
--runtime-tmpdir "%LOCALAPPDATA%\SakuraGTP\runtime"
```

注意语法必须用 %VAR%，写成 $VAR 不会被展开。
